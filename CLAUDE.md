# MyRpg — заметки для Claude

## Игра

RPG на ядре боя Людъмака: рюкзак-сетка с соседством по тегам, автобой, парирование в реальном времени. Сейчас это шаблон механик с минимальным наполнением — дальше механики заполняются новым контентом. Экраны: главный (инвентарь 5×5, выдача любого предмета героя, выбор врага, «В бой») и бой с одним врагом. Подробности механик джема — `docs/jam/CLAUDE-jam.md`.

Наполнение сейчас:
- **Герой:** 4 предмета — стальной меч (пассивный, основное оружие для парирования), краюха хлеба (пассивная еда с зарядами), лечебный эликсир (активный, 1 заряд), точильный камень (амулет с аурой).
- **Соседство:** 2 правила — «Алхимия к оружию» (+25% урона) и аура точильного камня (+10% урона соседнему оружию). Движок умеет и другие виды эффектов без правил: отключение, отравление, взрыв в начале боя, замедление, усиление ауры, внешний запрет (`BlockRule`).
- **Враг:** крестьянин с вилами: вилы и коровьи лепёшки (снаряд с зарядом, пропущенная оставляет пятно). Атака одного вида — обычный удар на месте (`AttackKind = 'hit'`).
- **Модификатор врага:** «Пьяный» (урон +50%, 25% промахов) — в `battle.ts` работает, в игре не выдаётся (бой с `mod: null`).
- Цена (`ITEM_STATS.price`) и редкость (`ItemDef.tier`) предметов лежат в данных, не используются.

Как добавлять контент: предмет — `data/items.ts` + `ITEM_STATS`; враг — `data/enemies.ts` + `ENEMY_STATS` (+ портрет); предмет врага — `data/enemyItems.ts` + `ENEMY_ITEM_STATS`; правило соседства — запись в `data/synergies.ts` + число в `SYNERGY`; тег — `data/tags.ts`; основное оружие — `parryPerk` у предмета и запись в `PARRY_CURSOR.weapons`. Новый вид атаки, перк парирования или характеристику предмета (блок, оглушение…) нужно дописывать в `battle.ts` и сцену боя.

Роли: пользователь — геймдизайнер (дизайн и баланс), код пишет Claude.

## Стек

Phaser 4 + TypeScript + Vite. Конфиг: WebGL, Scale FIT, базовое разрешение 1920×1080, `roundPixels`. Других зависимостей нет.

Команды:
- `npm run dev` — игра на http://localhost:5173;
- `npm run build` — `tsc` и сборка в `dist/` (относительные пути);
- `npm run typecheck`.

`src/systems/`, `src/data/`, `src/config/` не импортируют Phaser (логика боя должна работать без графики — пригодится для будущих симуляций). Phaser — только в сценах, `ui.ts` и `components/`.

Арта нет, кроме портретов врагов (`public/assets/portraits/enemies/*.webp`, ключи и пути — `enemyKey` / `enemyPortraitPath` в assets.ts). Шрифт системный (`FONT` в ui.ts). Предметы — цветные плитки с названием (цвет по категории — `CATEGORY_COLORS` в ui.ts).

## Структура

```
src/
  main.ts              — конфиг Phaser, список сцен
  state.ts             — предметы в инвентаре, основное оружие, выбранный враг; добавить, выбросить, потратить заряд
  ui.ts                — цвета, текст, кнопка, портрет врага (или плашка), описания предметов словами
  components/GridView.ts — одна сетка для всех мест: 'edit' (инвентарь: перетаскивание, ПКМ — поворот,
                         двойной клик — основное, за сетку — выбросить), 'battle' (клик — активный предмет), 'view' (сумка врага)
  scenes/BootScene.ts  — грузит портреты врагов
  scenes/MainScene.ts  — главный экран: инвентарь 5×5, сила снаряжения, выдача предметов, выбор врага, «В бой»
  scenes/BattleScene.ts — бой с одним врагом поверх BattleSim: кружки атак и парирование ПКМ, журнал, «Ещё раз» / «На главный»
  config/balance.ts    — все числа баланса: герой (HERO_HP), инвентарь (BACKPACK_MASK 5×5), сила врагов (ENEMY_STAT_MULT),
                         предметы героя и врагов, соседство, парирование, модификатор
  config/feel.ts       — ощущения: цифры, тряска, кружки атак и парирование, пороги перетаскивания и двойного клика
  config/assets.ts     — портреты врагов, курсор-клинок основного оружия (PARRY_CURSOR), раскладки BATTLE_LAYOUT и MAIN_LAYOUT
  data/                — предметы героя (items), предметы врагов (enemyItems), враги (enemies), теги (tags),
                         правила соседства (synergies), модификатор врага (modifiers)
  systems/             — backpack (сетки и размещение), synergy (соседство), battle (BattleSim — вся логика боя)
docs/
  catalog.html         — каталог всего, что есть в игре (исходник артефакта «Каталог MyRpg», см. правило ниже)
  balance-guide.md     — гайд по балансу (от Fable): шкалы, формулы, соседство, навык, прогрессия, экономика, метрики
  phaser4-migration-map.md — что в Phaser-коде Людъмака ломается в v4
  jam/                 — справка из джема: CLAUDE-jam.md, designdoc.md, balance-report.md, stage1-report.md,
                         вывод симуляции джема sim-ludmak.txt / sim-new.txt (сверка переноса ядра на этапе 1)
```

Переходы: Boot → Main ⇄ Battle.

Бой: `new BattleSim({ items, enemy, mainUid })` (необязательно: `mod`, `rng`, `heroHp`). Статусы — `fight`, `won`, `lost`. Враг копит замах до перезарядки первого предмета с зарядами (по priority) и бьёт: удар летит кружком с окном парирования `FEEL.parry.window`. Парирование — ПКМ в поле атак (`BATTLE_LAYOUT.parryZone`); клинок отбивает отрезком от кончика до конца лезвия по числам `PARRY_CURSOR.weapons` (как картинка-курсор в Людъмаке), отбитый удар × `PARRY_DAMAGE_MULT`. Расходники тратятся навсегда (state.spendCharge).

Основы по гайду (уже в коде): шкала на границе гайда — меч 20, здоровье героя 200; две пары чисел масштабированы от джема отдельно: «длительность» (урон героя, здоровье врагов) ×10/3, «опасность» (урон врагов, здоровье героя, лечение) ×1.25 — новые числа держать в этих парах; бой дробный — округление вниз только при списании, остаток переносится на следующее срабатывание того же предмета (`BattleSim.whole`); фиксированный тик `BATTLE_TICK` 0.1 с (`step` копит время, кружки рисуются плавно через `BattleSim.progress`); перезарядка кратна тику и не меньше `MIN_COOLDOWN`; затяжной бой — `FATIGUE`. Соседство: все бонусы — «увеличение» в одну сумму; одно правило от нескольких соседей не складывается; не больше `SYNERGY_STACK.maxAuras` положительных бонусов; кап `capBonus`; аура не усиливает ауру; недействующие бонусы — `AppliedEffect.inactive`. Подсказки показывают реальный урон диапазоном (`hitRange` в ui.ts).

## Правила

- Данные игры — только в `src/data/*.ts`.
- Числа баланса — только в `src/config/balance.ts`, с комментарием, что число значит. Длительности, размеры и пороги эффектов — в `src/config/feel.ts`.
- Картинки — только через ключи из `src/config/assets.ts`. Сцены не обращаются к файлам напрямую. Координаты элементов экранов — в раскладках assets.ts, не в коде сцены.
- `src/systems/`, `src/data/`, `src/config/` не импортируют Phaser.
- Новые зависимости (кроме phaser, typescript, vite) — только с согласия пользователя.
- Делать только то, что попросили на текущий этап; не добавлять фичи и абстракции сверх задачи.
- Не удалять существующие файлы без подтверждения.
- **Не делать git commit** — коммиты делает пользователь сам, даже если в задаче написано «коммить после этапа».
- **Баланс и механики — по гайду `docs/balance-guide.md`,** если пользователь прямо не сказал иначе. Перед правкой формул, чисел, соседства, парирования, прогрессии или экономики сверяться с ним. Если запрос пользователя противоречит гайду, до выполнения сказать: какой раздел или пункт гайда нарушается, в чём именно расхождение и к чему оно ведёт (по разделам 8 и 10 гайда), и предложить 1–3 решения (как по гайду, компромисс, как просили — с ценой). Делать по запросу пользователя, если он подтвердил после предупреждения. Числа из гайда — стартовые; таблицу парирования (раздел 3.2) заменяет телеметрия.
- **Каталог игры держать актуальным.** Каталог — артефакт https://claude.ai/artifact/NK7EDTgXbKzbHge6h9H2wz, исходник — `docs/catalog.html`. Каждое изменение, которое меняет содержимое или правила игры (предметы, враги, предметы врагов, соседство, модификаторы, теги и категории, числа баланса, механики боя и инвентаря, экраны и управление), в той же задаче отражать в `docs/catalog.html`: правка строк таблиц, новая механика — новая страница-раздел в оглавлении, дата «Снято с кода …» — сегодняшняя. Затем перепубликовать артефакт по этому URL (Artifact с `url`, тот же файл) и сказать пользователю, что каталог обновлён. Числа в каталоге — как их считает игра (с множителями и округлением), брать из кода, не по памяти.
